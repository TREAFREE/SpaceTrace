# ADR-006：不可变观测端点与历史发现投影

## 背景

SpaceTrace 已在内部提供当前目录聚合以及有损的小时级/天级历史，并且具备一个纯函数式、确定性的路径分类器。这些数据面并不是审计级的发现来源。schema v11 现在能够持久化经过校验的版本化决策与纯投影结果。一次完整生产扫描也会在同一次遍历中采集仅目录测量、直接子级覆盖、带 birth time 复用防护的对象元数据和冻结分类；当持久卷与挂载代次已知时，一个事务会同时发布当前事实、连续 logical/allocated v11 观测帧，并登记确定性投影 work。projector 会在提交后处理新 work，也会在启动时恢复 pending work。扫描器仍不能产生显式 absent 端点，也不能证明目录 link-set 唯一，因此缺失行继续只是缺少证据，生产 move finding 继续被抑制；概览展示尚未接入。

FSEvents 报告的是有损且经过合并的失效提示。重命名标志既不包含可信的源/目标配对，也不包含持久的对象标识。扫描器会观测文件身份以在单次扫描期间避免重复计算已分配字节，也会为 v11 candidate 记录保守的目录对象元数据，但会明确把目录 link status 记录为 `unknown`。因此，名称、仅 inode、大小、时间戳接近程度、方向相反的增量或 FSEvents 重命名标志都不能证实发生了移动。

当前架构规定，分类器 schema 参与确定观测是否可比较。分类并不会改变测得的字节数，而且规则升级不得切断原本兼容的测量历史。分类应在测量比较之后进行，并且必须冻结到每一条历史发现中。

现有的历史排名查询可能同时返回父级和子级各自的包含增量。仅仅避免在 UI 中求和并不足够：排名列表仍可能把同一项物理变化呈现两次。产品必须先制定有文档说明、互不重叠的贡献策略，才能声称满足 FR-006。

最后，对账过程可能发现某条发现所依赖的证据已经失效。这与用一个修正后的解释替换原发现并不是同一种操作。发现本身仍然不可变；v11 可以追加一个范围严格受限的“证据已失效”撤回记录，而 replacement（替换）需要后续的更正模型和 schema。

## 决策驱动因素

- 每条发现必须可追溯至不可变的源端点，并且必须能够经受分类器升级而不被静默地重新解释。
- 未知、不完整、缺失、已撤销、未挂载或不连续的证据绝不能被转化为零、删除或移动。
- 移动检测必须优先保证精确率而非召回率，因为一次错误的移动判定就会损害产品的核心可信度。
- 父级与子级聚合必须产生互不重叠的排名贡献，并具有确定性的排序。
- 墙上时钟或时区变化不得改变提交顺序。
- 已失效的证据必须从当前有效视图中消失，同时不得抹除原始审计记录，也不得伪装成已经存在修正后的替代发现。
- 该设计必须保持仅使用元数据、本地运行、有界、无需 SQLite 即可测试，并与现有的模块化单体架构兼容。

## 已考虑的方案

### 方案 A——从当前小时级/天级历史读取模型生成发现

- 优点：对 schema 和应用程序的改动最少。
- 成本：没有不可变的源端点、没有显式缺失状态、没有可靠的移动证明，而且读取模型中可能不存在已删除路径。
- 风险：错误判定删除/移动、静默改写历史，以及父级/子级重复计算。
- 评估：否决。

### 方案 B——根据重命名事件、名称、大小或相邻且方向相反的增量推断移动

- 优点：表面上的召回率高，且几乎不需要扫描器工作。
- 成本：FSEvents 是有损的且不会配对路径；inode/名称/大小复用和复制操作都是常见反例。
- 风险：复制可能被判定为移动，两个无关目录可能被配对，不完整证据可能被转化为确信的结论。
- 评估：否决。

### 方案 C——不可变端点、显式缺失、纯函数式比较、冻结分类以及仅追加发现/撤回

- 优点：可审计的因果关系、对证据缺口采用封闭失败、确定性的移动证明、保留分类器版本，以及幂等的崩溃恢复。
- 成本：需要 schema-v11 表、额外的本地元数据、投影检查点、迁移以及更多保留策略工作。
- 风险：对象标识 API 需要经过跨版本验证；保守的抑制策略会降低召回率。
- 评估：选定。

## 决策

### 1. 不可变观测端点

发现所使用的每个端点都具有持久的端点 ID，并记录：

- 范围 ID；
- 持久卷身份；
- 挂载代次；
- 覆盖纪元；
- 主体标识及其依据（`stableFileSystemObject` 或 `normalizedPath`）；
- 规范化的不透明位置 ID；
- 度量；
- 路径语义版本和测量语义版本；
- 数据库生成的单调提交序列；
- UTC 墙上时钟时间；
- 一个明确状态：`present(bytes, coverage)`、`absent(parentAbsenceReference)` 或 `unknown(reason)`。

缺失端点是一个已存储的事实，而不是一条不存在的记录。它所携带的原始父级引用本身并不构成证明。应用层观测帧验证器必须将该引用解析为同一个兼容观测帧中的完整直接父级，才能提升缺失转换的语义。权限丢失、卸载、根目录被替换、未完成对账的事件缺口、不完整枚举以及缺少端点记录，均产生 `unknown`/不可比较证据。

### 2. 测量兼容性

仅当范围、持久卷身份、挂载代次、覆盖纪元、主体、标识依据、度量、路径语义和测量语义均匹配，并且比较端的提交序列严格大于基线端的序列时，两个端点才具有测量兼容性。

墙上时钟时间可能重复或倒退；排序由单调提交序列控制。分类器规则目录/规则版本**不**参与字节测量兼容性的判定。只有在兼容的 `StorageChange` 已经存在之后，才能进行分类。

预期内的证据不足返回一个带类型的 `incomparable` 结果。如果同一个不可变端点 ID 被复用于比较两端，系统会在兼容性检查之前返回独立的 `corrupt` 结果，避免将账本损坏隐藏成普通抑制。损坏的标识符、无效的状态构造、无效的持久化载荷和受检算术失败仍属于错误。

### 3. 变化与缺失语义

完整的 `present` 端点产生保持原度量类型的有符号包含增量。原始的 `absent` 到 `present` 以及 `present` 到 `absent` 比较只产生 `appearanceCandidate` 和 `disappearanceCandidate`；只有通过验证的应用层观测帧投影才能将其提升为出现和消失发现。产品文案不得声称用户在某个精确事件时刻创建或删除了数据；这些时间仅表示观测端点。

缺少对应端点、不完整值、`unknown` 状态或无效的父级证明，均不能产生因果性发现。第一个完整基线仍然仅具描述性。

### 4. 移动证明

端点比较器在确认端点级兼容、两端完整存在、使用稳定标识依据且位置发生变化后，可以产生 `relocationCandidate`。该候选并不是移动结论。仅当以下条件全部成立时，应用层观测帧投影才会产生移动发现：

1. 两个端点均为 `present` 且完整；
2. 两个端点属于同一个持久卷和同一挂载代次；
3. 两个端点使用同一个唯一且稳定的文件系统对象标识；
4. 源位置 ID 与目标位置 ID 不同；
5. 四个逻辑父级角（源/目标父级 × 基线/比较观测帧；允许父级重合）都具有完整且兼容的端点覆盖与直接子级覆盖；
6. 该标识在两个观测帧中均唯一，并且不存在硬链接/链接集合歧义；
7. 平台标识包含 inode 复用防护，例如可用的代次令牌，或创建时间加节点类型。

跨卷变化绝不能判定为移动。如果无法获得稳定标识或复用防护，SpaceTrace 可以报告路径出现/消失，也可以抑制该结论，但不得将这两个路径配对为移动。本决策不引入内容哈希，因为它会读取所需元数据之外的内容，而且无法区分复制与移动。

被监控根目录在其观测帧内没有父级，因此该投影无法为根目录位置变化满足父级覆盖证明。根路径被替换、重新挂载以及卷重新接入由被监控范围与挂载代次生命周期处理；这些事件会建立新的兼容基线或证据缺口，而不会生成根目录移动发现。

### 5. 父级/子级贡献与排名

对于一对兼容观测和一种度量：

```text
inclusiveDelta(node) = comparison(node) - baseline(node)

childFlowDelta(node)
  = sum(comparison immediate-directory-child bytes)
  - sum(baseline immediate-directory-child bytes)

exclusiveDelta(node) = inclusiveDelta(node) - childFlowDelta(node)
```

只有具有正排名贡献的 `growth`（增长）草稿或顶层显式 `appearance`（出现）草稿，才有资格进入正增长排名。这里的“顶层”是指该出现尚未被同一次观测帧比较中的祖先出现覆盖。增长使用正的 `exclusiveDelta`；顶层出现只使用一次其正的包含增量，并把未匹配的后代折叠到该出现之下。已确认的移动、零或负贡献、`decrease`（减少）以及 `disappearance`（消失）均不进入正增长 Top 10，但可以出现在单独的发现分组中。尤其需要注意：即使减去一个绝对值更大的负子级流量后，某条减少发现计算出了正的 `exclusiveDelta`，它仍然没有排名资格。

如果某个分支缺少计算排他贡献所需的完整直接子级观测帧，该分支即为排名不可比较。SpaceTrace 不得减去不完整的子级集合。已确认的祖先移动会吸收保持相同父子关系的隐式后代移动；发生独立重新挂接的后代仍作为单独的移动。

稳定的正增长排名键依次为：

1. 排名字节数降序；
2. 比较端提交序列降序；
3. 范围 ID 按二进制/UTF-8 升序；
4. 用于报告的不透明位置 ID 按二进制/UTF-8 升序；
5. 确定性发现键升序。

本地化显示名称、本地化路径、类别措辞、SQLite 行顺序和墙上时钟时间均不得作为最终的平局判定项。

### 6. 冻结分类证据

测量比较必须在分类之前完成。增长/出现使用比较端位置；消失使用基线端位置；移动同时保留源位置与目标位置的分类决策，并将目标位置视为主要的当前解释。

每个冻结决策都包含规则目录版本，以及以下状态之一：

- `classified`：类别、置信度、规则 ID、规则版本和不含路径的证据代码；
- `noMatchingRule`；
- `ambiguous`：按稳定顺序排列的竞争规则 ID。

耐久决策与发现投影载荷使用带显式判别字段或结构校验的格式。版本 1 解码器对未知字段、显式 `null`/非规范可选值、互相矛盾的状态、无效键、不一致的版本或序列、重复/非规范顺序，以及无法从保留草稿推导出的排名键一律封闭失败。在带 schema 版本的兼容策略获批之前，解码器不得静默丢弃或规范化不可变证据。

规则/规则目录升级不得改写或撤回较早的发现。若日后明确批准更正或替换，则必须在未来 schema 下创建独立版本化的投影与替换记录。

### 7. 仅追加投影与持久化义务

应用程序代码负责比较、分类、层级策略、发现投影，以及对带类型完整性对账的授权。持久化层存储不可变端点、观测帧、待处理的投影工作、发现和独立撤回记录；它不得判定证据是否意味着移动或消失，并且 schema v11 不存储后继或替换关系。

发现草稿通过端点 ID 引用其权威的基线与比较观测；草稿中复制的路径、显示名称、时间、覆盖状态和分类字段属于被冻结的解释证据，不能替代不可变观测帧账本。v11 持久化事务必须强制保证每条发现到两个端点记录及其所属观测帧的关联完整性，拒绝孤儿引用或跨帧引用，并确保被引用证据的保留时间至少与依赖它的发现相同。

Schema v11 必须：

- 添加仅追加的观测帧表和端点表，并包含父级/位置/对象证据；
- 持久化显式缺失以及不含路径的 `unknown`/缺口证据；
- 在一次完整扫描最终完成时，以原子方式登记投影工作；
- 保证投影在崩溃后具有幂等性；
- 持久化发现算法/排名版本、两个端点 ID、变化类型、包含增量、可选的排名贡献和冻结分类决策；
- 只持久化下文定义的版本 1 独立 `evidence_invalidated`（证据已失效）撤回，不添加后继/替换列；
- 根据 ADR-004，包含路径的端点/发现最多保留 30 天，之后仅保留获准且不含路径的健康/审计证据；
- 迁移每一个已发布的 golden fixture，并在失败时保留原始数据库。

任何当前的 v10 历史记录均不得被追溯性地呈现为不可变端点。第一个 v11 观测帧是一个描述性基线。

### 8. “证据已失效”撤回与未来替换

一条不可变发现由原始发现记录及其权威端点、冻结分类、算法/排名版本、规范草稿摘要和投影上下文共同构成。后续完整性工作即使不再信任这些证据，也不得更新其中任何字段。普通保留策略可以删除完整的到期图，但绝不能原地编辑发现。

Schema v11 只支持一种独立、仅追加的撤回原因：`evidence_invalidated`（证据已失效）。撤回仅表示原发现的证据未通过带类型的完整性检查，因此该发现不再属于当前有效结果。它不声称存在修正后的类别、数值、路径、原因或后继发现，也不满足 replacement/supersession（替换/取代）要求。

只有显式的带类型对账或完整性工作流才能请求撤回。请求必须标识准确的已存储发现，并携带其准确的已存储规范草稿摘要。后续缺少路径、重命名提示、相似或相同大小、分类器/规则目录升级以及用户清理操作，都绝不能推断或请求撤回。未知目标或与当前存储值不匹配的草稿摘要必须封闭失败。

该授权必须形成可执行的 API 边界，而不是调用方约定。公开历史仓库只暴露读取、观测帧最终化和投影工作，不暴露撤回变更。应用层内部的完整性授权器读取带类型的完整性失败和已存储审计记录，并且是唯一可以构造不可 `Codable` 的证据失效命令的代码；该命令没有 `public` 或 `package` 初始化器，发现 ID 与草稿摘要必须从已存储记录复制，而不是接受 UI 输入。持久化层只通过 package 范围的对账端口接收该能力，并仍在事务中重新校验目标与摘要。UI、分类器、用户清理和普通扫描调用方既不能构造，也不能调用这个变更面。

撤回的幂等性以请求为范围。使用相同请求 ID 和相同规范请求摘要重复调用时，返回已经提交的撤回；使用同一请求 ID 但改变任何字段属于不可变冲突；对已经撤回的目标使用第二个请求 ID 同样属于冲突。撤回以原子方式提交，并且只与目标保留同样长的时间；保留事务必须按依赖顺序把撤回、发现、投影、端点及相关证据作为一个完整图删除。目标到期后不得留下脱离目标的审计标记。

当前有效查询排除当前存在撤回记录的任何发现，即使查询把发现限制在更早的比较序列之前也一样。该序列上界约束的是观测/发现时间，并不提供“截至某时点”的更正视图。独立的审计读取仍返回未经改变的原发现及其可选撤回记录。因此，schema v11 不声称支持历史时点更正语义。

主要发现 UI 不得把已撤回发现呈现为当前结果。审计/详情 UI 继续显示它，并标记为**证据已失效**；不得声称该发现已修复、已替换、已删除或已清理，也不得暗示任何文件系统操作。精确措辞、可见性、无障碍和本地化仍属于受发布门禁约束的 UI 工作。

真正的更正或替换需要未来获批的模型：冻结的更正输入、生成器/版本注册表、更正工作及幂等请求所有权、版本化的更正投影、显式后继关系、保留/崩溃恢复语义、基准证据，以及 schema 迁移和 ADR 修订。V11 的撤回不关闭仍未完成的 replacement/supersession 门禁。

### 9. 隐私边界

原始路径、显示名称、不透明对象令牌、规范化位置键、时间线以及分类决策，即使经过哈希处理，也属于 `Sensitive`（敏感）级本地数据。对象令牌和原始路径不得进入证据代码、发布日志、遥测或默认诊断信息。SpaceTrace 必须继续仅使用元数据，并且不得为了建立标识而读取任何文件内容。

## 后果

### 正面影响

- 发现具有可审计的因果端点与确定性语义。
- 权限/挂载/事件缺口会以封闭失败方式处理，而不会虚构删除。
- 分类器变化不再破坏测量连续性或改写历史。
- 排他贡献消除了父级/子级在 Top 10 中重复计算的缺口。
- 崩溃恢复能够从持久的待处理工作中继续执行幂等投影。
- 当前有效读取可以对失效证据封闭失败，同时审计读取保留不可变原记录与撤回记录。

### 负面影响与接受的权衡

- v11 需要更多记录、索引、迁移 fixture 和保留策略工作。
- 某些文件系统可能无法提供可靠的目录标识；在这些情况下必须抑制移动发现。
- 保守的显式缺失规则与排名完整性要求会降低表面召回率。
- 现有 v10 小时级/天级历史无法升级为审计级端点。
- V11 撤回只具有当前有效性语义；替换与历史时点更正仍未实现。

### 中性影响或后续工作

- ADR-003 和 ADR-004 仍处于提议中，并且需要通过各自的采纳门禁。
- 显式 absence 采集、生产 APFS link-set/稳定身份资格、概览/菜单栏 UI、语料库扩充、导出以及 macOS 15.6 资格验证仍是彼此独立的阶段。
- 更正/替换模型、后继 schema 和仅追加取代证据仍是独立的采纳门禁；v11 撤回并未完成这些工作。
- 观测到的消失描述的是某个路径处的证据；它绝不授权删除操作，也不构成可回收性结论。
- 每个类别和发现都只是对已观测元数据的解释，绝不是删除指令、清理建议或安全保证。

## 验证计划

当前主机 schema v11 持久化与生产路径证据记录在 [SQLite v11 历史账本](../../engineering/sqlite-v11-historical-ledger.zh-CN.md)。它关闭了迁移、不可变帧/finding 提交、完整扫描 paired 发布、幂等即时/启动投影、证据失效撤回、有序保留、已发布恢复夹具及 50 万/100 万行当前主机 persistence 门禁，但不关闭显式 absence、稳定 move 证明、最低系统、UI、分类语料、导出、分发或维护者接受门禁。

1. 领域测试覆盖每一种兼容性不匹配、不完整/`unknown` 状态、显式缺失、严格序列排序、墙上时钟回拨、受检算术以及 Codable 重新验证。
2. 应用程序测试覆盖增长、减少、出现、消失、稳定移动、仅重命名证据的否决、标识歧义、祖先移动折叠、子级重新挂接、排他贡献、输入顺序排列组合以及稳定的 Top 10。
3. 文件系统测试覆盖目录标识可用性、inode 复用防护、硬链接、符号链接、克隆、并发重命名/删除、APFS 映像重新挂载/替换以及非 APFS 情况下的抑制。
4. 持久化测试覆盖观测帧/发现的原子提交、崩溃后幂等的投影、基于准确摘要的撤回幂等/冲突、当前有效与审计读取、v11 中不存在后继数据面、v6-v10 golden fixture 迁移、磁盘空间耗尽、损坏、迁移回滚、WAL 恢复以及与目标绑定的 30 天保留策略。
5. 引入 v11 后，500,000/1,000,000 行基准测试必须仍满足 PRD 的数据库与查询预算。
6. 发布/隐私扫描必须证明路径、显示名称、对象令牌或数据库转储均不会进入日志或默认诊断信息。
7. 在 macOS 15.6 和当前稳定版 macOS 上，真实的签名沙盒流程覆盖重启、权限撤销、外部卷重新接入，以及受控的创建/删除/重命名。

## 重新审视的触发条件

- 某个受支持的文件系统无法提供带有可接受 inode 复用防护的稳定对象令牌。
- 采用 30 天保留策略和选定节点策略后，端点账本超过 250 MB 基准。
- 排他贡献无法满足查询延迟要求，或在新支持的聚合类型下产生误导性结果。
- 产品需求增加跨卷移动语义、叶文件历史或超过 30 天的保留期限。
- Apple 推出能够提供持久源/目标对象标识的公开且保护隐私的事件 API。
