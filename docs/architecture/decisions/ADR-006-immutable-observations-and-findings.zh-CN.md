# ADR-006：不可变观测端点与历史发现投影

## 状态

提议中——可以实现并测试纯函数式的端点与投影契约，但在 schema-v11 迁移、崩溃恢复、保留策略、隐私、基准测试和 macOS 15.6 门禁全部通过之前，持久化与发布工作必须继续将本决策视为尚未采纳。

日期：2026-08-11

负责人：SpaceTrace 维护者

相关需求：FR-004、FR-005、FR-006、FR-007、FR-008、FR-012、FR-013、NFR-001、NFR-003、NFR-006

取代：无

被取代：无

## 背景

SpaceTrace 已经发布当前目录聚合以及有损的小时级/天级历史，并且具备一个纯函数式、确定性的路径分类器。这些数据面并不是审计级的发现来源。历史读取模型不会保留不可变的逐节点端点 ID、稳定的目录对象标识、基于完整父级观测的缺失证据、挂载代次，也不会保留每一个已删除端点。当前分类器尚未与历史结果相连接。

FSEvents 报告的是有损且经过合并的失效提示。重命名标志既不包含可信的源/目标配对，也不包含持久的对象标识。扫描器观测 `st_dev` 和 `st_ino`，仅用于在单次扫描期间避免因硬链接而重复计算已分配字节；它不会为目录持久化该标识。因此，名称、大小、时间戳接近程度、方向相反的增量或 FSEvents 重命名标志都不能证实发生了移动。

当前架构规定，分类器 schema 参与确定观测是否可比较。分类并不会改变测得的字节数，而且规则升级不得切断原本兼容的测量历史。分类应在测量比较之后进行，并且必须冻结到每一条历史发现中。

现有的历史排名查询可能同时返回父级和子级各自的包含增量。仅仅避免在 UI 中求和并不足够：排名列表仍可能把同一项物理变化呈现两次。产品必须先制定有文档说明、互不重叠的贡献策略，才能声称满足 FR-006。

最后，对账过程可能会纠正一个临时解释，同时不能删除其审计元数据；而发现按定义是不可变的。因此，持久化需要采用仅追加的取代关系，而不是原地更新。

## 决策驱动因素

- 每条发现必须可追溯至不可变的源端点，并且必须能够经受分类器升级而不被静默地重新解释。
- 未知、不完整、缺失、已撤销、未挂载或不连续的证据绝不能被转化为零、删除或移动。
- 移动检测必须优先保证精确率而非召回率，因为一次错误的移动判定就会损害产品的核心可信度。
- 父级与子级聚合必须产生互不重叠的排名贡献，并具有确定性的排序。
- 墙上时钟或时区变化不得改变提交顺序。
- 该设计必须保持仅使用元数据、本地运行、有界、无需 SQLite 即可测试，并与现有的模块化单体架构兼容。

## 已考虑的方案

### 方案 A——从当前小时级/天级历史读取模型生成发现

- 优点：对 schema 和应用程序的改动最少。
- 成本：没有不可变的源端点、没有显式缺失状态、没有可靠的移动证明，而且读取模型中可能不存在已删除路径。
- 风险：错误判定删除/移动、静默改写历史，以及父级/子级重复计算。
- 评估：否决。

### 方案 B——根据重命名事件、名称、大小或相邻且方向相反的增量推断移动

- 优点：表面上的召回率高，且几乎不需要扫描器工作。
- 成本：FSEvents 是有损的且不会配对路径；inode/名称/大小复用和复制操作都是常见反例。
- 风险：复制可能被判定为移动，两个无关目录可能被配对，不完整证据可能被转化为确信的结论。
- 评估：否决。

### 方案 C——不可变端点、显式缺失、纯函数式比较、冻结分类以及仅追加发现

- 优点：可审计的因果关系、对证据缺口采用封闭失败、确定性的移动证明、保留分类器版本，以及幂等的崩溃恢复。
- 成本：需要 schema-v11 表、额外的本地元数据、投影检查点、迁移以及更多保留策略工作。
- 风险：对象标识 API 需要经过跨版本验证；保守的抑制策略会降低召回率。
- 评估：选定。

## 决策

### 1. 不可变观测端点

发现所使用的每个端点都具有持久的端点 ID，并记录：

- 范围 ID；
- 持久卷身份；
- 挂载代次；
- 覆盖纪元；
- 主体标识及其依据（`stableFileSystemObject` 或 `normalizedPath`）；
- 规范化的不透明位置 ID；
- 度量；
- 路径语义版本和测量语义版本；
- 数据库生成的单调提交序列；
- UTC 墙上时钟时间；
- 一个明确状态：`present(bytes, coverage)`、`absent(parentAbsenceReference)` 或 `unknown(reason)`。

缺失端点是一个已存储的事实，而不是一条不存在的记录。它所携带的原始父级引用本身并不构成证明。应用层观测帧验证器必须将该引用解析为同一个兼容观测帧中的完整直接父级，才能提升缺失转换的语义。权限丢失、卸载、根目录被替换、未完成对账的事件缺口、不完整枚举以及缺少端点记录，均产生 `unknown`/不可比较证据。

### 2. 测量兼容性

仅当范围、持久卷身份、挂载代次、覆盖纪元、主体、标识依据、度量、路径语义和测量语义均匹配，并且比较端的提交序列严格大于基线端的序列时，两个端点才具有测量兼容性。

墙上时钟时间可能重复或倒退；排序由单调提交序列控制。分类器规则目录/规则版本**不**参与字节测量兼容性的判定。只有在兼容的 `StorageChange` 已经存在之后，才能进行分类。

预期内的证据不足返回一个带类型的 `incomparable` 结果。如果同一个不可变端点 ID 被复用于比较两端，系统会在兼容性检查之前返回独立的 `corrupt` 结果，避免将账本损坏隐藏成普通抑制。损坏的标识符、无效的状态构造、无效的持久化载荷和受检算术失败仍属于错误。

### 3. 变化与缺失语义

完整的 `present` 端点产生保持原度量类型的有符号包含增量。原始的 `absent` 到 `present` 以及 `present` 到 `absent` 比较只产生 `appearanceCandidate` 和 `disappearanceCandidate`；只有通过验证的应用层观测帧投影才能将其提升为出现和消失发现。产品文案不得声称用户在某个精确事件时刻创建或删除了数据；这些时间仅表示观测端点。

缺少对应端点、不完整值、`unknown` 状态或无效的父级证明，均不能产生因果性发现。第一个完整基线仍然仅具描述性。

### 4. 移动证明

端点比较器在确认端点级兼容、两端完整存在、使用稳定标识依据且位置发生变化后，可以产生 `relocationCandidate`。该候选并不是移动结论。仅当以下条件全部成立时，应用层观测帧投影才会产生移动发现：

1. 两个端点均为 `present` 且完整；
2. 两个端点属于同一个持久卷和同一挂载代次；
3. 两个端点使用同一个唯一且稳定的文件系统对象标识；
4. 源位置 ID 与目标位置 ID 不同；
5. 源观测帧与目标观测帧均具备对相关父级的完整覆盖；
6. 该标识在两个观测帧中均唯一，并且不存在硬链接/链接集合歧义；
7. 平台标识包含 inode 复用防护，例如可用的代次令牌，或创建时间加节点类型。

跨卷变化绝不能判定为移动。如果无法获得稳定标识或复用防护，SpaceTrace 可以报告路径出现/消失，也可以抑制该结论，但不得将这两个路径配对为移动。本决策不引入内容哈希，因为它会读取所需元数据之外的内容，而且无法区分复制与移动。

### 5. 父级/子级贡献与排名

对于一对兼容观测和一种度量：

```text
inclusiveDelta(node) = comparison(node) - baseline(node)

childFlowDelta(node)
  = sum(comparison immediate-directory-child bytes)
  - sum(baseline immediate-directory-child bytes)

exclusiveDelta(node) = inclusiveDelta(node) - childFlowDelta(node)
```

只有正的 `exclusiveDelta` 才有资格进入正增长排名。顶层的显式出现如果没有可比较的子级端点，则仅使用一次其包含增量。已确认的移动、零贡献、减少或消失不进入正增长 Top 10，但可以出现在单独的发现分组中。

如果某个分支缺少计算排他贡献所需的完整直接子级观测帧，该分支即为排名不可比较。SpaceTrace 不得减去不完整的子级集合。已确认的祖先移动会吸收保持相同父子关系的隐式后代移动；发生独立重新挂接的后代仍作为单独的移动。

稳定的正增长排名键依次为：

1. 排名字节数降序；
2. 比较端提交序列降序；
3. 范围 ID 按二进制/UTF-8 升序；
4. 用于报告的不透明位置 ID 按二进制/UTF-8 升序；
5. 确定性发现键升序。

本地化显示名称、本地化路径、类别措辞、SQLite 行顺序和墙上时钟时间均不得作为最终的平局判定项。

### 6. 冻结分类证据

测量比较必须在分类之前完成。增长/出现使用比较端位置；消失使用基线端位置；移动同时保留源位置与目标位置的分类决策，并将目标位置视为主要的当前解释。

每个冻结决策都包含规则目录版本，以及以下状态之一：

- `classified`：类别、置信度、规则 ID、规则版本和不含路径的证据代码；
- `noMatchingRule`；
- `ambiguous`：按稳定顺序排列的竞争规则 ID。

耐久决策使用带显式判别字段的对象格式。在带 schema 版本的兼容策略获批之前，
解码器必须拒绝未知字段或互相矛盾的字段，不得静默丢弃不可变证据。

规则/规则目录升级不得改写较早的发现。若日后明确批准重新计算，则必须创建另一个带版本的投影或一条取代原发现的新发现。

### 7. 仅追加投影与持久化义务

应用程序代码负责比较、分类、层级策略和发现投影。持久化层存储不可变端点、观测帧、待处理的投影工作、发现及取代关系；它不得判定证据是否意味着移动或删除。

Schema v11 必须：

- 添加仅追加的观测帧表和端点表，并包含父级/位置/对象证据；
- 持久化显式缺失以及不含路径的 `unknown`/缺口证据；
- 在一次完整扫描最终完成时，以原子方式登记投影工作；
- 保证投影在崩溃后具有幂等性；
- 持久化发现算法/排名版本、两个端点 ID、变化类型、包含增量、可选的排名贡献、冻结分类决策以及可选的 `supersedes_finding_id`；
- 根据 ADR-004，包含路径的端点/发现最多保留 30 天，之后仅保留获准且不含路径的健康/审计证据；
- 迁移每一个已发布的 golden fixture，并在失败时保留原始数据库。

任何当前的 v10 历史记录均不得被追溯性地呈现为不可变端点。第一个 v11 观测帧是一个描述性基线。

### 8. 隐私边界

原始路径、显示名称、不透明对象令牌、规范化位置键、时间线以及分类决策，即使经过哈希处理，也属于 `Sensitive`（敏感）级本地数据。对象令牌和原始路径不得进入证据代码、发布日志、遥测或默认诊断信息。SpaceTrace 必须继续仅使用元数据，并且不得为了建立标识而读取任何文件内容。

## 后果

### 正面影响

- 发现具有可审计的因果端点与确定性语义。
- 权限/挂载/事件缺口会以封闭失败方式处理，而不会虚构删除。
- 分类器变化不再破坏测量连续性或改写历史。
- 排他贡献消除了父级/子级在 Top 10 中重复计算的缺口。
- 崩溃恢复能够从持久的待处理工作中继续执行幂等投影。

### 负面影响与接受的权衡

- v11 需要更多记录、索引、迁移 fixture 和保留策略工作。
- 某些文件系统可能无法提供可靠的目录标识；在这些情况下必须抑制移动发现。
- 保守的显式缺失规则与排名完整性要求会降低表面召回率。
- 现有 v10 小时级/天级历史无法升级为审计级端点。

### 中性影响或后续工作

- ADR-003 和 ADR-004 仍处于提议中，并且需要通过各自的采纳门禁。
- 扫描器标识、SQLite v11、投影器持久化、概览/菜单栏 UI、语料库扩充、导出以及 macOS 15.6 资格验证仍是彼此独立的阶段。
- 观测到的消失描述的是某个路径处的证据；它绝不授权删除操作，也不构成可回收性结论。

## 验证计划

1. 领域测试覆盖每一种兼容性不匹配、不完整/`unknown` 状态、显式缺失、严格序列排序、墙上时钟回拨、受检算术以及 Codable 重新验证。
2. 应用程序测试覆盖增长、减少、出现、消失、稳定移动、仅重命名证据的否决、标识歧义、祖先移动折叠、子级重新挂接、排他贡献、输入顺序排列组合以及稳定的 Top 10。
3. 文件系统测试覆盖目录标识可用性、inode 复用防护、硬链接、符号链接、克隆、并发重命名/删除、APFS 映像重新挂载/替换以及非 APFS 情况下的抑制。
4. 持久化测试覆盖观测帧/发现的原子提交、崩溃后幂等的投影、仅追加取代、v6-v10 golden fixture 迁移、磁盘空间耗尽、损坏、迁移回滚、WAL 恢复以及 30 天保留策略。
5. 引入 v11 后，500,000/1,000,000 行基准测试必须仍满足 PRD 的数据库与查询预算。
6. 发布/隐私扫描必须证明路径、显示名称、对象令牌或数据库转储均不会进入日志或默认诊断信息。
7. 在 macOS 15.6 和当前稳定版 macOS 上，真实的签名沙盒流程覆盖重启、权限撤销、外部卷重新接入，以及受控的创建/删除/重命名。

## 重新审视的触发条件

- 某个受支持的文件系统无法提供带有可接受 inode 复用防护的稳定对象令牌。
- 采用 30 天保留策略和选定节点策略后，端点账本超过 250 MB 基准。
- 排他贡献无法满足查询延迟要求，或在新支持的聚合类型下产生误导性结果。
- 产品需求增加跨卷移动语义、叶文件历史或超过 30 天的保留期限。
- Apple 推出能够提供持久源/目标对象标识的公开且保护隐私的事件 API。
