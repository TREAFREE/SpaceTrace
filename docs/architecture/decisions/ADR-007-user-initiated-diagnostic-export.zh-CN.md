# ADR-007：使用窄化保存能力的用户主动诊断导出

## 状态

已接受

日期：2026-08-13

英文原文：[ADR-007-user-initiated-diagnostic-export.md](ADR-007-user-initiated-diagnostic-export.md)。英文文档是工程事实源，本文件用于中文阅读。

## 背景

SpaceTrace 需要一种用户能够先检查、再保存且不会自动上传的支持资料。FR-014 要求写入前预览、默认路径脱敏、完整路径单独确认，以及可从中断中安全恢复。沙盒 App 之前只声明 `com.apple.security.files.user-selected.read-only`，它不能授权向 `NSSavePanel` 选中的文件写入。

Apple 的“用户所选位置读写” entitlement 粒度较粗：它可能授权修改用户选择的位置。因此，即使 SpaceTrace 只需要创建一个导出文件，启用它仍会扩大理论攻击面。这个扩展不能削弱“被观察文件与目录始终只读”的产品规则。

## 决策

1. 沙盒 App 只声明 App Sandbox、App 范围 bookmark 和 `com.apple.security.files.user-selected.read-write` 三项 entitlement。
2. 被监控目录的授权仍然显式只读。`SecurityScopedWatchedScopeCatalog` 使用 `.securityScopeAllowOnlyReadAccess` 创建 bookmark；生产文件系统端口不提供写入、删除、移动、改权限、触发下载或清理被观察数据的操作。
3. 只有用户从“诊断导出”页面主动打开 `NSSavePanel` 并选择精确目标文件后，才使用写 entitlement。应用绝不会静默选择保存位置。
4. 每次导出在保存面板出现前展示栏目与数量预览。文档只包含有界的 App/系统/架构元数据、覆盖状态、类型化无路径健康事件，以及最多 100 条用户选择的历史发现；不包含文件内容、bookmark 字节、网络目标或自动上传动作。
5. 默认使用脱敏模式。主目录根、被监控根和剩余路径组件会被替换为惰性标签或 96 位 token；token 由本次导出独立的 256 位随机盐派生。盐不会写入文件，因此 token 无法跨导出关联，也无法通过持久字典反推。
6. 完整路径必须经过警告和确认，且授权绑定一个导出 UUID。保存、取消、失败或开始下一次导出都会使该授权失效。
7. 准备好的文档上限为 2 MiB。数据先同步写入权限为 `0700` 的私有 Application Support 暂存目录，暂存文件权限为 `0600`，随后原子提交到用户所选目标。取消或提交前失败会删除半成品并保留已有目标文件。启动恢复只删除 UUID 命名的普通 `.partial` 文件，不跟随符号链接，也不删除未知条目。
8. 导出格式为 JSON schema version 1，并使用确定性键顺序。它记录 `includesFileContents = false`、`uploadsAutomatically = false`、所选路径模式、冻结的分类规则/目录证据和类型化发现有效性。本决策不增加生产导入或上传入口。
9. 发布打包器必须在 entitlement 集不是精确三项时封闭失败。修改 entitlement、导出上限、脱敏算法、上传边界或监控目录访问模式，都需要重新进行 ADR 与安全审查。

## 已考虑方案

| 方案 | 优点 | 成本 / 失败模式 | 结论 |
| --- | --- | --- | --- |
| 保存面板单文件导出 + 受控读写 entitlement | 原生用户选择；普通 JSON；沙盒内可用 | entitlement 比单文件更粗，需要严格代码和发布门禁 | 采用 |
| 保持只读 entitlement，通过非沙盒 helper 复制 | 主 App entitlement 不变 | 新增高权限信任边界、IPC、签名、更新和清理复杂度 | 拒绝 |
| 只导出到 Application Support | 无需扩展 entitlement | 用户不便检查或分享，不符合 FR-014 | 拒绝 |
| 自动上传支持资料 | 支持流程方便 | 引入网络、同意、保留、认证和泄露风险 | 拒绝 |
| 默认导出原始路径 | 调试信息最完整 | 违背最小化原则，暴露个人名和项目名 | 拒绝 |

## 后果

### 正面

- 用户控制何时导出、导出什么以及保存到哪里。
- 默认产物有诊断价值，同时不会形成稳定的跨导出路径关联。
- 取消、写失败与重启清理都有类型化且可测试的行为。
- 支持人员无需接收文件内容，也能检查精确版本、覆盖、健康码和冻结规则证据。

### 负面与已接受权衡

- 沙盒 entitlement 可能授予比实现意图更大的写权限；代码审查和 API 形状本身属于安全边界。
- 即使经过明确确认，完整路径导出仍然敏感。
- ad-hoc 构建仍不具备发布者验证与公证；导出安全不代表已经具备公开发布资格。
- 文件写入完成后，其保护取决于用户所选位置的权限、备份和同步设置。

### 护栏

- 监控代码只接收只读 bookmark 证据，并且不能引用导出写入器。
- 导出代码不包含 `URLSession`、共享服务、shell、Quick Look 或文件内容枚举。
- UI 和错误可以显示目标文件名，但不得记录或持久化其完整路径。
- 私有暂存目录排除在扫描和诊断日志之外。
- 测试覆盖授权不匹配、token 单次稳定/跨次隔离、选择上限、精确字节与权限、取消、失败保护、符号链接安全恢复，以及无上传字段。

## 验证计划

1. 运行应用层、平台层、严格并发、隐私与 Release 构建门禁。
2. 检查源码与签名 App entitlement；必须是精确三项，并拒绝旧只读 key 和任何附加 key。
3. 使用签名沙盒构建选择监控目录，完成重启、撤权和恢复；证明 bookmark 仍只读，监控不会修改内容。
4. 导出脱敏 JSON，检查全部字段，并证明用户名、监控路径组件、bookmark 字节和随机盐都不存在。
5. 确认一次完整路径后取消，再启动下一次导出，证明必须重新确认。
6. 在暂存阶段取消、模拟目标写失败、跨启动保留受控 partial，验证清理与目标文件保护。
7. 对预览、警告、选择、进度、错误和成功状态执行 VoiceOver、纯键盘、减少动态效果、增强对比度和大字号审查。
8. 在授权 GitHub 预发布之前，重复全新安装、quarantine、替换升级、macOS 15.6 和 DMG 验证。

## 重新评估触发条件

- Apple 提供更窄的“用户选择单文件创建”沙盒 API。
- 导出需要压缩、附件、文件内容、共享服务或网络上传。
- 安全审查发现监控目录能力可到达修改操作。
- 导出 schema 或脱敏算法需要向后兼容消费。
- 选择 Mac App Store 或非沙盒分发配置。
