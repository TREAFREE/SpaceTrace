# ADR-008：仅追加的校准修订与更正投影

## 状态

提议中

日期：2026-08-13

英文原文：[ADR-008-append-only-reconciliation-corrections.md](ADR-008-append-only-reconciliation-corrections.md)。工程实现以英文文档为事实源，本文件为完整中文对照版。

相关需求：FR-004、FR-005、FR-006、FR-007、FR-012、FR-013、NFR-001、NFR-003、NFR-006

接受后修订：[ADR-006](ADR-006-immutable-observations-and-findings.zh-CN.md)

## 背景

FSEvents 只能告诉 SpaceTrace 某个区域可能已经过期；它不提供字节差值，也不提供可信的精确事件序列。因此，SpaceTrace 只有在完整校准扫描之后，才会发布当前目录事实和审计级历史 finding。扫描受预算限制，脏工作是持久化的，schema v11 会保存完整、不可变的观测帧与 finding。

目前还存在两个彼此不同的更正问题：

1. 小时级和天级目录历史读模型在一个尚未结束的时间桶中属于临时结果。同一时间桶内的后续完整扫描目前会替换由 `(stream, path, bucket kind, bucket start)` 选中的行。显示值会更准确，但较早修订及其扫描关系没有作为显式审计链保留。
2. 已获批的 finding 算法、排名策略或冻结分类输入如果存在缺陷，可能需要对完全相同的不可变帧对重新投影。Schema v11 可以追加 `evidence_invalidated`（证据已失效），但不能指向更正投影，不能表示“更正后没有 finding”的结果，也不能说明哪个投影替换了较早解释。

不能用任意一次后续扫描重写较早时间区间。后续扫描包含原比较之后发生的文件系统变化，它不是时间机器。后续发现的证据可以使较早 finding 失效，但只有在更正输入仍描述完全相同的观测区间时，才能更正那个较早值。这些时间边界必须进入数据模型，而不能只靠 UI 措辞解释。

FR-004 还要求产品展示最近一次成功校准以及仍待处理的根目录，并证明“模拟事件缺口后发生 5 GiB 变化”的场景可以通过有界校准恢复。这些是应用层义务；只新增 successor 表并不能满足它们。

## 决策驱动因素

- 永不更新或静默重新解释不可变观测、finding 或已提交投影。
- 后续完整扫描更正当前时间桶时，保留较早临时历史修订及其扫描元数据。
- 只有完全相同的原始帧对与已注册的确定性实现，才允许产生更正后的 finding 投影。
- 绝不因为后续 finding 的路径、大小、名称或类别相似，就把它关联到较早区间。
- 让当前有效查询保持简单、确定，同时保留完整审计链。
- ACK 丢失、重试、保留、迁移和损坏必须封闭失败。
- 继续遵守 30 天路径历史边界，以及一百万节点数据库小于 250 MB 的门禁。
- 原始路径、标识符、更正输入、摘要和时间线必须留在本机，且不得进入诊断。

## 已考虑的方案

### 方案 A——原地更新较早历史行或 finding 行

- 优点：查询与 schema 改动最小。
- 代价：会销毁先前向用户展示了什么、为什么展示的证据。
- 风险：静默重写历史、重试语义不清、无法独立审计。
- 结论：拒绝。

### 方案 B——把所有更正都当作 `evidence_invalidated`

- 优点：schema v11 已经支持。
- 代价：只能说明证据失效，不能提供更正后的数值或投影。
- 风险：可能把失效错误描述成更正，FR-004 仍未完成。
- 结论：仅保留给无法安全重建的证据；作为更正模型则拒绝。

### 方案 C——把任意后续 finding 关联为后继

- 优点：可以复用后续已有投影。
- 代价：后续比较覆盖的是不同时间区间，可能混入无关变化。
- 风险：形成错误的时间因果关系和误导性的更正字节数。
- 结论：拒绝。

### 方案 D——分离读模型修订与同证据更正投影

- 优点：两类更正都具有诚实的时间语义；临时汇总与审计级 finding 使用不同的证明要求。
- 代价：需要 schema v12、生成器注册表、两条显式更正工作流、迁移、恢复、保留与 UI 工作。
- 风险：记录数量增加，当前有效查询更复杂。
- 结论：采用。

## 决策

### 1. 两条更正通道

Schema v12 提供两条互相独立的仅追加通道：

- **校准修订**记录完整扫描对临时小时级或天级目录汇总的每次修订。它会更正当前读模型，但不修改任何较早修订。
- **更正投影**使用显式注册的生成器与冻结更正输入，对完全相同的不可变观测帧重新投影。它可以替换当前有效投影，同时保留前驱投影和全部原始 finding。

两条通道都不修改 schema-v11 行。Schema v11 的含义继续严格遵守 ADR-006。

### 2. 仅追加的校准修订

每次完整校准发布都会为每个受影响的目录/时间桶键追加一个修订。修订冻结：

- 数据库分配的正整数修订 ID；
- scope/stream 身份、时间桶类型和起始时间；
- 目录 subject/location 引用与度量值；
- coverage 与后代数量；
- 终态扫描运行 ID、脏工作 revision 与观测时间；
- 同一个完全一致时间桶键的可选直接前驱修订 ID；
- 带版本的规范载荷摘要。

前驱必须是该键当前的终端修订。第一个修订没有前驱。另一个时间桶里的后续修订只是普通历史，不形成更正边。只有来自完整扫描、且其脏工作 revision 在原子发布竞争中仍然有效的修订才可接受。

普通 Overview 查询为每个键选择终端修订。审计查询返回完整前驱链。原始修订永不更新。迁移期间，schema v12 可以继续把既有物化表作为事务内维护的缓存，但它绝不是更正事实源。

### 3. 已注册的同证据更正投影

更正投影冻结：

- 16 字节请求 ID 与规范请求摘要；
- 前驱投影 ID 及其精确已存投影摘要；
- 与前驱相同的 baseline/comparison 帧 ID；
- 已注册的 finding 算法、排名策略和更正输入格式版本；
- 冻结更正输入及其 SHA-256 摘要；
- 完整、确定性的替换生成结果，包括合法的空结果；
- 数据库分配的更正提交序列与 UTC 提交时间。

替换对象是完整投影，不是针对单个 finding 的补丁。其 baseline/comparison 帧对必须与前驱逐字节一致。至少一个已注册的语义输入版本必须发生变化；使用相同版本与输入重放属于幂等，不属于更正。

Application 为每个受支持的更正版本组合维护封闭注册表。Persistence 会重新加载两个不可变帧、解析精确注册表条目、重新生成完整结果，并要求值相等且规范摘要相等后才提交。未知版本、输入缺失、不受支持的分类器迁移、部分帧或结果不匹配都必须封闭失败。

### 4. 后继图与当前有效查询

投影替换形成线性、仅追加的链：

- 一个投影最多有一个直接后继；
- 一个更正投影恰好有一个直接前驱；
- 后继与前驱使用相同帧对；
- 环、分支、自链接、跨 scope 链接和跨 metric 链接全部拒绝；
- 整条链使用由原始观测帧对确定的同一个保留锚点与过期边界。

当前有效视图解析终端投影，只返回该投影的 finding 与排名，并排除附着于该终端投影的独立证据失效撤回。Schema v11 撤回覆盖原始 finding；ADR-009 增加 schema v13 的独立目标，以便在不重写冻结 v12 的前提下覆盖 corrected finding。审计视图按链顺序返回所有未修改的投影、finding、更正边、冻结输入摘要和撤回。

除非调用方显式请求审计链，否则 schema v12 不声称提供“更正前应用当时相信什么”的历史查询。comparison-sequence 上限仍然是观测时间边界，而不是更正时间快照。

### 5. 后续证据与诚实的时间语义

后续文件系统证据可以：

- 为它自己的时间桶追加新校准修订；
- 当它证明较早 finding 的证据不可用时，追加 `evidence_invalidated` 撤回；
- 为后续帧对生成普通 finding。

除非更正工作流拥有仍然描述完全相同较早帧对的完整、不可变输入，否则后续证据不能成为那个较早帧对的更正投影。名称、路径、大小、对象号复用、后续 absent 或用户断言都不能凭空制造这种证明。无法重建时，诚实结果是“证据已失效/未知”，而不是更正后的字节值。

### 6. 授权与幂等

公开 history repository 只暴露读取。更正命令不可 `Codable`、仅 package 可见，并且只有 Application 更正授权器在重新加载前驱审计记录、验证已注册更正输入、复制已存 ID/摘要后才能构造。UI 代码不能直接提供 finding/projection ID、摘要、版本或 successor。

事务只有三种结果：新提交；请求/结果逐字节相同时返回已提交；否则返回不可变冲突。请求摘要覆盖全部版本、前驱身份/摘要、冻结更正字节和生成结果。ACK 丢失后的重试必须返回原提交，不能再次分配投影或更正边。

### 7. 校准状态

应用状态从持久化事实派生，并按 watched scope 暴露：

- 最近一次成功提交的完整校准时间与提交序列；
- 是否仍有脏工作待处理；
- 可取得时，最早待处理工作的观测/revision；
- 带类型的不可用、需要权限、卷不可用、部分、失败或历史关闭状态。

不得用空数组或可选日期替代这些状态。墙钟时间只用于展示；数据库序列与脏 revision 决定顺序。Overview 与菜单栏绝不能把待处理值显示成完整结果。

### 8. 保留、恢复与隐私

所有修订和更正链都必须处在配置的 1～30 天路径历史边界内。链在共享过期时间到达时按依赖顺序原子删除；保留过程不能在语句之间让前驱重新成为当前有效结果。History Off 使用既有显式策略停止新增带路径修订/投影并删除它们，同时保留运行所需的当前状态。Clear History 仍是独立的完整重置。

迁移使用原子迁移前备份以及已发布 schema-v11/v12 fixture。恢复绝不发明缺失 successor，也不从未验证 JSON 重建。主库/WAL 损坏继续执行既有隔离与只读恢复策略。

原始路径、subject/location ID、帧/投影 ID、更正输入、请求摘要与更正时间都属于本机敏感数据。它们不得进入日志和默认诊断导出。除非未来 ADR 明确批准，导出最多包含带类型、无路径的更正数量/状态。

## 后果

### 正面影响

- 更正临时历史值时，不再抹去用户可能已经看过的较早修订。
- 算法与分类更正保持精确的帧/时间语义。
- 更正投影可以合法地包含零个 finding，而不必假装某条任意 finding 替换了另一条。
- 当前有效读取与审计读取具有彼此独立、可测试的含义。
- FR-004 可以端到端验证，不需要从一个 successor 列推断已经完成。

### 负面影响与接受的权衡

- Schema v12 增加存储、查询、迁移和保留复杂度。
- 需要不可获得历史证据的更正仍然只能成为“失效/未知”；为了可信度，召回率会更低。
- 只要保留期内的更正工作可能引用旧实现，生成器注册表就必须保留对应受支持实现。
- 保守的路径历史预算可能比无限历史产品更早删除完整审计链。

### 护栏

- 不可变修订、投影、finding 或更正行不暴露 UPDATE surface。
- SQLite trigger 与 repository 验证分别拒绝非法图边和不兼容帧对。
- 查询先重建并验证规范值，再应用 limit。
- 生成器实现必须纯函数、确定、有界，并在源码中注册且带 fixture vector。
- 只有存在已提交修订/投影边时，UI 才能使用“校准后已更正”；否则必须显示待处理、不可用或证据已失效。

## 验证计划

1. 每个新契约测试都必须先因为 v12 模型缺失而失败。
2. 只有在包含更正行和 WAL/SHM 的一百万节点发布工作负载仍小于 250 MB 后，才能冻结精确 schema、整数码、摘要格式、索引与查询计划。
3. 将确定性 v11 fixture 迁移到 v12；证明回滚、备份恢复、ACK 丢失幂等、不可变冲突、损坏隔离和未知版本拒绝。
4. 证明同一时间桶内多次完整扫描会追加前驱链，Overview 只选择终端修订，同时审计读取保留全部修订。
5. 证明同帧、已注册重投影可以产生变化结果、空结果和重新排名结果；跨帧、未注册、分支、环和伪造更正必须封闭失败。
6. 模拟事件缺口，制造受控的 5 GiB allocated 变化，运行有界校准，在正确 watched subtree 满足 KPI-02，同时原始审计元数据仍可查询。
7. 验证最近成功/待处理根状态在取消、部分 coverage、superseded、睡眠/唤醒、撤权、卷返回、重启、History Off 和保留后的行为。
8. 更改发布决定前，运行隐私、严格并发、schema fixture、50 万/100 万 benchmark、签名沙盒、macOS 15.6、无障碍、DMG 与发布候选门禁。

## 重新评估触发条件

- APFS snapshot 或其他平台 API 能重建可信的较早文件系统状态。
- 更正需要跨越不同观测帧对。
- 产品需要按更正提交时间查询历史状态，或允许分支专家意见。
- 保留策略需要让更正审计元数据比带路径证据保存更久。
- 更正输入需要导入、网络同步或用户编写的证据。
