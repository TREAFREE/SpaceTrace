# ADR-010：非商业源码可见许可与贡献者权利

## 状态

已接受

日期：2026-08-14

英文原文：[ADR-010-noncommercial-source-available-licensing.md](ADR-010-noncommercial-source-available-licensing.md)。英文文档是产品与工程事实源，本文件用于中文阅读。本记录不是法律意见，也不替代具有约束力的许可证或贡献者协议。

## 背景

SpaceTrace 公开源代码并接受 Pull Request，但维护者不授权普通接收者将 SpaceTrace 或修改版用于商业用途，因此 MIT 已被拒绝。如果仓库没有许可证，虽然 GitHub 用户可以通过平台查看与 fork 公开仓库，却不会获得清晰的一般性使用、修改和分享权，这也不符合预期的协作方式。

维护者还希望保留未来将 SpaceTrace 商业化的选择。公开的非商业许可证本身不会把外部贡献者拥有的版权商业再许可权授予维护者。因此，仓库需要两项彼此独立的授权：面向普通接收者的公开非商业许可证，以及让贡献者保留所有权、同时向项目所有者授予附加权利的贡献者协议。

## 决策

1. SpaceTrace 使用未经修改的官方 [PolyForm Noncommercial License 1.0.0](../../../LICENSE.md)，SPDX identifier 为 `PolyForm-Noncommercial-1.0.0`。
2. 公开许可证允许非商业使用、修改和分发，但不向普通接收者授予商业使用权。法律直接赋予的合理使用等权利不受影响。
3. SpaceTrace 将自身描述为**源码可见（source-available）**，而不是 OSI 定义下的“开源软件”，因为商业用途限制不符合 Open Source Definition。
4. 发布工具通过 SHA-256 冻结官方许可证文本，并在 `licenseDeclared` 与 `licenseConcluded` 中写入精确 SPDX identifier。DMG 安装说明和第三方声明必须披露非商业边界与官方许可证 URL。
5. 仓库欢迎 Pull Request，但只有每位贡献者都明确接受带版本的 [SpaceTrace Contributor License Agreement](../../../CONTRIBUTOR_LICENSE_AGREEMENT.md)，外部贡献才可以合并。
6. 贡献者保留版权。CLA 向项目所有者单独授予全球性、非独占、永久、不可撤销且免版税的版权和专利许可，其中包括再许可及商业/专有分发权；它不会扩大普通接收者在 PolyForm 下的权利。
7. 当前贡献流程把项目所有者定义为控制 GitHub 账户 `TREAFREE` 并拥有 `TREAFREE/SpaceTrace` 的个人或法律实体。进行重大商业交易前，必须在合同和项目记录中一致识别该个人或实体，并应取得适用司法辖区的专业法律复核。
8. 不能仅凭讨论推定贡献者接受 CLA。接受必须由 Pull Request 中明确勾选 CLA 并提交贡献形成记录。维护者必须保留该记录，且不得合并无权授权或拒绝 CLA 的贡献。
9. 第三方代码继续受其自身许可证约束，只有完成兼容性、notice、来源和 SBOM 审查后才可纳入；SpaceTrace CLA 不能修复不兼容的第三方权利。

## 已考虑方案

| 方案 | 优点 | 成本 / 失败模式 | 结论 |
| --- | --- | --- | --- |
| PolyForm Noncommercial 1.0.0 + CLA | 清晰支持非商业协作；保留维护者商业化选择；贡献者保留所有权 | 不是 OSI 开源；CLA 增加贡献摩擦且需要法律复核 | 采用 |
| MIT | 常见且获 OSI 批准；贡献阻力小 | 允许任何人商业化修改版，违背所有者决定 | 拒绝 |
| 不提供许可证 | 不会意外授予过宽权利 | 无法清晰允许非商业使用、修改和分享，不符合预期协作方式 | 拒绝 |
| PolyForm Noncommercial、无 CLA | 公开限制清晰；仓库政策简单 | 外部贡献若未另行获权或重写，无法安全用于商业再许可 | 拒绝 |
| 版权转让 | 集中式商业控制最强 | 转移贡献者所有权，产生明显更大的法律和社区摩擦 | 拒绝 |

## 后果

### 正面

- 非商业用户可以按明确条款使用、修改和分享 SpaceTrace。
- 普通接收者不能依据项目许可证进行商业使用。
- 维护者可以商业化完全自有的代码，也可以在 CLA 有效接受后商业化已接收的外部贡献。
- SPDX、notices、README、PR 流程和发布验证共享一个由机器测试的 identifier。

### 负面与已接受权衡

- SpaceTrace 不能准确宣传为 OSI 批准的开源软件。
- 一些贡献者可能拒绝 CLA，其工作将无法合并。
- 勾选框和仓库定义的所有者是实用证据，但不能替代适用司法辖区的法律意见或商业合同中的具名法律主体。
- 外部贡献代码未来能否换许可证，受每位贡献者实际有效授予的精确权利限制。

### 护栏

- 不得修改官方许可证文本来加入项目专属条款；运行说明应写入 README、notices、本 ADR 或 CLA。
- 不得把 PolyForm 描述为允许普通接收者商业使用、再许可或按 OSI 开源方式使用。
- 未保留 Pull Request 中的明确接受记录，不得声称贡献受 CLA 覆盖。
- 不能因为提交者勾选了 CLA，就接受复制来的第三方代码。
- 修改 CLA 主体、范围或接受流程，需要法律与维护者复核，并同步更新自动化契约。

## 验证计划

1. 使用冻结的官方 SHA-256 逐字节验证 `LICENSE.md`。
2. 验证 README、CONTRIBUTING、PR 模板、SPDX、notices、DMG 安装说明和发布资格输入都使用精确 identifier，且不再保留 MIT/`NOASSERTION` 当前状态。
3. 运行贡献许可契约，证明贡献者所有权、项目所有者商业权、普通接收者限制和 PR 明确接受始终存在。
4. 运行打包测试，并检查只读 DMG 中的精确许可说明和官方 URL。
5. 合并外部 PR 前，确认每位提交作者都接受了同一 CLA 版本，并保留 Pull Request 记录。
6. 商业分发包含外部贡献的版本前，对贡献者接受记录和项目所有者法律身份进行专业法律复核。

## 重新评估触发条件

- 项目所有者、仓库所有权或商业分发主体发生变化。
- SpaceTrace 改用 OSI 批准许可证、其他源码可见许可证、付费商业许可证或应用商店分发协议。
- 贡献者质疑 CLA 有效性或无权授予相关权利。
- 项目开始大规模接收组织所有的贡献。
- 适用司法辖区的复核要求改变法律适用、签署、隐私或记录保留方式。
