## 目标与当前边界

SpaceTrace 现在可以比较两个经过验证的不可变目录观测帧，并为增长、减少、出现、消失以及经过严格证明的移动生成确定性发现草稿。它还可以在不重复计算同一项父级/子级流量的前提下生成正增长排名。

纯投影现在已经接入生产完整扫描路径。扫描器会在同一次遍历中产出仅目录 logical/allocated 测量、完整直接子级覆盖、冻结的版本化分类，以及 APFS 对象号/birth time 证据。在提交后续帧前，一个纯应用层对账器只会为以下顶层节点补充 absent 端点：该节点此前完整存在，并且其未移动的当前直接父级拥有完整测量与直接子级枚举。Apple 明确说明 APFS 不支持目录硬链接，因此这些 APFS 目录对象可以携带唯一 link-set 证据；不受支持的文件系统继续使用路径身份且不能判定移动。随后，一个 SQLite 事务会发布当前事实与 paired v11 观测帧并登记投影 work；projector 会在提交后处理，也会在启动时恢复。真实 Foundation 集成已经证明增长、同卷移动和消失。概览现会读取有界的 current-effective 与不可变审计记录，分离证据失效项，保留冻结分类证据，展示 History Off/baseline-unavailable 状态，并明确标注 metric、完整证据和观测时间段。经过审阅的 v2 分类语料以 64 个已知和 32 个 Unknown 场景关闭了 FR-007/KPI-03 仓库门禁。菜单栏继续承担 FR-009 所定义的独立、有界 24 小时卷状态。它不会使旧小时级/天级 SQLite 历史自动达到审计级。replacement/supersession、用户明确控制的导出/脱敏证据、人工辅助技术复核，以及真实 macOS 15.6 资格验证仍是发布阻断项。

link-set 策略遵循 Apple 的 [APFS 兼容性指南](https://developer.apple.com/library/archive/documentation/FileManagement/Conceptual/APFS_Guide/FAQ/FAQ.html)；受控 APFS 磁盘镜像测试验证了重命名会保留稳定对象身份，而 Foundation 目录链接尝试不会共享该身份。目录 `st_nlink` 不会被用作唯一性证明。

FSEvents 仍然只是失效提示。任何事件标志、文件名、时间戳或方向相反的字节增量组合，都不能单独生成一条发现。

## 三层模型的职责边界

| 层 | 负责 | 明确不负责 |
| --- | --- | --- |
| 领域层端点 | 某一提交序列下的单个节点；范围、卷、挂载代次、覆盖纪元、主体标识及依据、不透明位置、度量、语义版本、观测时间，以及显式 `present`/`absent`/`unknown` 状态 | 路径文本、树形拓扑、分类、跨观测帧移动证明或排名 |
| 应用层观测帧 | 一棵规范的有根目录树；路径和显示名称；直接父级拓扑；直接子级枚举覆盖；冻结分类；可选稳定对象资格证据 | 耐久 SQLite 身份、取代关系、UI 文案或清理策略 |
| 应用层投影结果 | 由两个观测帧确定性生成的发现草稿——类型、端点 ID、冻结解释证据、包含增量、可选非重叠排名贡献和算法/排名版本——以及稳定排名键和带类型抑制摘要 | 权威端点记录的所有权、持久化寿命或修改用户数据的权限 |

数据只能单向流动：

```text
不可变端点
    |
    v
经过验证的基线/比较观测帧
    |
    v
纯端点比较 + 观测帧级证明
    |
    v
不可变发现草稿 + 稳定排名键 + 抑制摘要
```

草稿会复制展示观测结果所需的敏感解释字段，但通过端点 ID 引用权威的基线和比较观测；它不会内嵌一份权威观测帧账本。后续持久化事务必须把这些 ID 解析到不可变端点记录及其所属观测帧；包含孤儿引用或跨帧引用的草稿绝不能提交。

## 观测帧准入与证据状态

`HistoricalFindingObservationFrame` 只接受非空、规范的有根目录树。在同一个观测帧内：

- 端点、主体、不透明位置以及二进制路径标识各自唯一；
- 每个节点具有相同的范围、持久卷、挂载代次、覆盖纪元、度量、路径/测量语义以及提交序列；
- 每个非根节点都在真实的路径组件直接父路径上具有一个可用直接父级；
- 目录度量只能是逻辑字节或已分配字节，不能是卷可用字节；
- `present` 节点具有被冻结的版本化分类决策；
- `absent` 或 `unknown` 节点没有分类，而且其直接子级覆盖为 `unknown`；
- 端点测量覆盖与直接子级枚举覆盖始终是两个独立事实。

排序由提交序列而非墙上时钟时间确定。比较观测帧的序列必须严格大于基线。UTC 观测时间仍作为展示与审计证据保留，但在系统校时后可能重复或倒退，绝不能作为排名键。

### 度量文案与限制

- `logical` 是按照扫描器已声明语义汇总的可见/表观文件长度。它不是物理磁盘占用；稀疏文件、克隆、占位文件或多重链接内容都可能使它高估实际占用。
- `allocated` 是扫描器能够观测到的元数据所报告已分配块汇总，只包含扫描器已说明的单次运行内硬链接去重。它不代表 APFS 唯一所有权、克隆精确归属、快照占用、可清除容量或保证可回收空间。
- 目录发现观测帧拒绝 `volumeAvailable`。卷级可用容量及其归因属于独立模型，不能混入目录子级流量运算。
- 与快照有关的观测和估算不属于 finding metric v1。若未来引入，UI 与无障碍 value 必须在程序化语义和视觉上把“估算值”与实测字节明确区分。

后续 UI 必须持续显示度量名称与覆盖限制。任何一种度量都不得改写成 Apple“系统数据”、精确物理归属或“可以安全回收的空间”。

### 显式缺失是证据，不是缺少记录

一个 `absent` 端点包含 `ParentAbsenceReference`。观测帧验证会在同一帧中解析该引用，并且只在它指向该节点完整、存在的直接父级，同时该父级的直接子级枚举完整时接受它。

这一差异可以防止虚假的删除结论：

- 完整父级枚举加上显式缺失端点，可以支持出现/消失转换；
- 缺少端点记录只代表缺少证据；
- 不完整测量、不完整子级枚举、权限撤销、卷未挂载、新的覆盖纪元或 `unknown` 端点，绝不会被转换成零或缺失。

预期内的证据缺口会计入带类型的抑制摘要。损坏性的不可变端点 ID 复用与受检算术溢出仍是错误，不会被隐藏为普通抑制。

## 发现语义

| 发现 | 所需证据 | 含义与文案限制 |
| --- | --- | --- |
| `growth`（增长） | 相同主体和位置、兼容且完整存在的两个端点、正包含增量 | 两个端点之间观测到更多字节；不能据此判断创建进程或精确事件时间 |
| `decrease`（减少） | 相同主体和位置、兼容且完整存在的两个端点、负包含增量 | 观测到更少字节；不能据此证明用户执行了删除，也不能证明空间可回收 |
| `appearance`（出现） | 显式缺失的基线、完整存在的比较端，以及经过验证的父级缺失证明 | 该目录在一次完整观测中缺失，并在之后的观测中存在 |
| `disappearance`（消失） | 完整存在的基线、显式缺失的比较端，以及经过验证的父级缺失证明 | 该目录在一次完整观测中存在，并在之后的观测中缺失；不能据此证明由谁移除了它 |
| `move`（移动） | 两个完整存在的端点，加上下文列出的全部移动证明条件 | 同一个经过资格验证的文件系统对象，被观测到位于同一个已挂载卷代次中的不同位置 |

未变化的比较不会生成发现。未知、不完整、不兼容或未匹配的证据不会生成因果性发现。第一份完整观测帧没有更早的不可变端点可供比较，因此只具有描述性。

分类发生在字节兼容性判定之后。在每个可用端点上，成功分类会冻结类别、置信度、规则 ID/版本、catalog 版本和无路径证据代码；无匹配会冻结准确 Unknown 原因；歧义会按规范顺序冻结所有竞争规则 ID。之后的规则目录升级既不会破坏测量连续性，也不会静默重新解释较早的草稿。分类器契约详见[确定性存储分类引擎](deterministic-attribution.zh-CN.md)。

## 移动证明与子树折叠

一个位置变化候选只有在以下条件全部成立时才能提升为 `move`：

1. 两个端点均存在、完整且兼容；
2. 范围、持久卷、挂载代次、覆盖纪元、度量、主体以及稳定对象标识依据一致；
3. 源与目标不透明位置 ID 不同；
4. 两端具有同一个稳定文件系统对象令牌；
5. 复用防护一致：要么是非空代次令牌，要么是纳秒级创建时间加节点类型；
6. 两个观测帧中的链接状态都明确为 `unique`，绝不能是 `ambiguous` 或 `unknown`；
7. 源父级和目标父级各自在基线帧与比较帧中存在，覆盖全部四个逻辑父级角（源/目标 × 基线/比较；其中两个角可以解析到同一个父级），而且每个相关父级的端点覆盖和直接子级覆盖都完整；
8. 如果某个相关父级自身发生移动，则该父级移动已经得到证明。

该策略优先保证精确率而不是召回率。跨卷或跨挂载变化绝不是移动。缺少稳定标识、复用防护不一致、链接歧义、父级证据不完整、仅有路径标识或任一端不可用，都会抑制移动结论。SpaceTrace 不使用内容哈希，也不会读取文件内容。

被监控根目录在其观测帧内没有父级，因此无法满足四父级证明。根目录被替换、重新挂载以及外置卷返回属于被监控范围、Disk Arbitration 和挂载代次生命周期的职责。它们会产生新的基线或显式证据缺口，而不会产生根目录移动发现。

当一个祖先移动已得到证明时，如果某个未变化后代仍保持相同直接父子关系以及二进制相对后缀，那么它只是祖先移动的隐含组成部分，会被折叠。如果后代自身还有字节变化，则会生成一条增长/减少草稿，其移动上下文引用祖先移动。发生独立重新挂接或重命名的后代不会被静默吸收。

## 包含贡献与非重叠贡献

对于一个兼容节点和一种度量：

```text
inclusiveDelta(node) = comparison(node) - baseline(node)

childFlowDelta(node)
  = sum(comparison immediate-directory-child bytes)
  - sum(baseline immediate-directory-child bytes)

exclusiveDelta(node) = inclusiveDelta(node) - childFlowDelta(node)
```

所有加减运算都经过溢出检查；发生溢出即生成失败。只有当两端直接子级列表完整，而且每个直接子级都具有完整测量时，才可以得到排他贡献（显式缺失的子级贡献零）。SpaceTrace 绝不会减去不完整的子级集合。

### 父级/子级示例

| 节点 | 基线 | 比较端 | 包含增量 | 子级流量 | 排他贡献 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 父级 | 20 GiB | 25 GiB | +5 GiB | +5 GiB | 0 GiB |
| 直接子级 | 8 GiB | 13 GiB | +5 GiB | 0 GiB | +5 GiB |

正增长排名只通过子级报告一次 5 GiB，不会把父级和子级呈现为相互独立的 10 GiB 增长。

顶层显式出现——即尚未被祖先出现覆盖的出现——只使用一次它的正包含增量，作为该分支的非重叠贡献；未匹配后代会折叠到它之下。在不存在可比较基线子级端点时，这就是出现语义对应的排他贡献。

只有具有正非重叠贡献的 `growth` 与顶层 `appearance` 草稿才有资格进入正榜。移动、消失、零/负贡献或减少均没有资格。类型资格与正负号相互独立：例如，父级减少 10 GiB，而其子级合计减少 30 GiB 时，计算出的排他值为 +20 GiB，但该发现仍然是 `decrease`，不得进入正增长 Top 10。

## 稳定输出与排名顺序

版本 1 按以下顺序排列有资格的草稿：

1. 非重叠排名字节数降序；
2. 比较端提交序列降序；
3. 范围 ID 按原始 UTF-8 字节升序；
4. 用于报告的不透明位置 ID 按原始 UTF-8 字节升序；
5. 结构化发现键升序。

发现键由算法版本、排名策略版本、两个端点 ID、发现类型以及冻结的规则目录版本共同派生。使用二进制 UTF-8 比较是有意设计：大小写不同，以及 Unicode 规范等价但字节不同的文件系统名称仍保持不同。本地化路径、本地化显示名称、分类文案、Swift `Hasher`、输入顺序、SQLite 记录顺序与墙上时钟时间都不能用于最终平局判定。

保留的发现数组与抑制原因数组同样采用规范顺序。结果还会记录超过配置的 `1...100` 上限后被截断的正增长发现数量。

## 封闭失败的 Codable v1 边界

当前 Codable 数据面是严格的版本 1 耐久交换契约，不是宽松的 JSON 输入接口。`HistoricalFindingGenerationResult` 是完整顶层信封；下级值只是规范组成部分，不是可以独立信任的因果记录。解码和编码会重新验证所有能够从载荷自身推导的不变量。实现会拒绝的情况包括但不限于：

- 未知字段或未知判别值；
- 在规范格式要求省略可选键时提供显式 `null`；
- 相互矛盾的存在/缺失/分类组合；
- 复用端点 ID、非法路径、非法拓扑，以及任何使用非递增序列的因果草稿；一对非递增观测帧只允许表示为“空批次 + 一条带类型的帧级抑制”；
- 无法根据草稿证据重新计算出的键；
- 不匹配的度量、算法版本、排名策略版本或规则目录版本；
- 重复或非规范排序的发现/原因；
- 缺失、无资格、顺序错误或超过上限的排名键；
- 与保留批次互相矛盾的抑制/截断摘要。

无路径的抑制/折叠计数不会为了自证而复制每一个被抑制端点，因此仅凭紧凑结果无法证明其精确因果数量。v11 提交边界必须解析两份观测帧账本，并在接受结果前重新计算或进行完整关联验证；仅仅成功解码 JSON 绝不构成持久化授权。

这一封闭失败规则可以防止未来生产者把被静默忽略的证据塞入不可变 v1 载荷。未来格式演进必须采用显式 schema/版本兼容策略和迁移，不能依赖 Swift 默认忽略未知键字段的行为。

## 隐私与产品文案边界

原始路径、显示名称、不透明位置 ID、稳定对象令牌、用于复用防护的创建时间、时间线以及冻结分类决策都属于敏感本地数据。哈希处理不会使这些字段自动适合遥测。它们不得进入 Release 日志、分析数据、证据代码、崩溃标题或默认诊断。测试与文档只能使用合成路径。

投影继续保持仅使用元数据并在本地运行。一条发现只能解释两个观测，不能证明归属、意图、进程来源、精确事件时间、可恢复性或可安全删除。尤其需要遵守：

- “消失”不得改写成“用户删除了它”；
- “减少”不得改写成“你可以回收的空间”；
- 类别不是清理建议；
- 任何发现都不授权删除、清理、隔离或其他修改操作。

## 已实现的生产边界与剩余门禁

现有 schema-v10 小时级/天级读取模型不能被追溯性地当作不可变 finding 证据。生产流水线现在会写入第一份描述性 v11 基线，只有后续兼容完整观测帧才登记确定性 work。SQLite 会重新加载权威帧并重新生成紧凑结果，然后才提交投影。

已经实现的边界包括：

1. 仅追加的 paired logical/allocated 观测帧、父级拓扑、两种覆盖维度、冻结分类、不可变提交序列，以及数据库强制的端点/帧引用；
2. 原子完整扫描 finalization：发布当前事实并登记确定性投影 work，History Off 继续不写入路径历史；
3. 幂等即时/启动投影、证据失效撤回、有序保留、已发布 v10/v11 fixture、类型化恢复，以及当前主机 500,000/1,000,000 行门禁。

已经实现的生产证据边界还包括：

1. 对紧邻上一份 logical 帧执行顶层 present-to-absent 对账，并验证父级未移动、测量完整、直接子级完整、路径/位置一致以及上一端点完整；
2. 仅对 APFS 使用由卷身份、对象号和纳秒 birth time 派生的稳定 subject，并依据平台文件系统不变量标记唯一 link status；
3. 真实临时目录增长/重命名/删除投影，以及可选启用的 APFS 镜像重命名/重挂/换卷资格测试。

剩余 finding 门禁包括：

1. 增加获批的 replacement/supersession 模型；v11 仅支持证据失效，不含 successor 链接；
2. 在 macOS 15.6 与当前稳定版 macOS 上，为已实现的概览完成人工键盘、VoiceOver、对比度、大字体和不确定性措辞复核；
