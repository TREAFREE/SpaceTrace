# First Implementation Slice Status

Status: **Architecture spike with directory permission, baseline, and history overview flows**

Last verified: 2026-08-13

Chinese companion translation: [implementation-status.zh-CN.md](implementation-status.zh-CN.md). This English document remains the architecture source of truth.

This document records what the first implementation slice proves and, equally importantly, what it does not prove. ADR-003, ADR-004, and ADR-006 remain **Proposed** until their complete validation plans and maintainer review are satisfied.

## Deliberately not claimed

- The user-facing multi-directory permission list, batch baseline, startup-volume capacity history, version/schema metadata, restart restoration, power/thermal/sleep-aware pause/retry, schema-v10 Overview/menu-bar history, immutable finding Overview, schema-v11 persistence, complete-scan paired finalization, complete-parent disappearance reconciliation, qualified APFS stable moves, bounded immediate/launch projection, FR-007/KPI-03 repository corpus gate, and user-controlled redacted diagnostic export are implemented. Production scans freeze directory-only logical/allocated evidence, direct-child coverage, classification, and APFS object/reuse evidence from one traversal; real Foundation growth/rename/delete and controlled APFS image tests pass. The Overview reads persisted current-effective and invalidated-audit records without reclassification and exposes typed History Off/baseline-unavailable states. Unproved missing rows and unsupported filesystems remain suppressed; replacement/supersession remains open. APFS unique-block accounting and true in-enumerator mid-scan continuation also remain open. The export entitlement and real signed-sandbox save flow now pass current-host qualification; manual assistive-technology, clean-account Gatekeeper-exception, packaged bookmark-continuity, and macOS 15.6 qualification remain open.
- The corrected current-host run closes the ad-hoc 24-hour process/endurance gate for commit `ed0d660`. Activity Monitor CPU/wakeup/memory/I/O and thermal intervals are energy-related evidence, not direct watt/joule measurement, and this result does not prove a universal scheduler-delivery guarantee, signed status-item interaction matrix, Apple-identity distribution, release-candidate replacement, or macOS 15.6 runtime qualification.
- User-started baseline scheduling reacts to sleep, Low Power Mode, serious/critical thermal state, and observes the active power source. Background rate budgets, system-load scheduling, and the architecture's token bucket are not implemented. Hard-link deduplication is bounded by the entry budget but remains in memory for each scan run.
- Real sandbox Powerbox presentation and stale/identity-failure reauthorization UI are implemented. Current-host persistent selection, same-bundle relaunch, explicit app-level removal, and same-image external-volume return have passed. Genuine stale evidence, the different-UUID replacement subcase in the UI flow, Apple-identity signing, and the macOS 15.6 runtime matrix remain incomplete or blocked by the available host.
- The controlled current-host UI fixture is eight-for-eight and checks important accessibility names, values, and hittability. It is not a manual assistive-technology qualification and does not prove VoiceOver pronunciation, Full Keyboard Access order, or layout under increased contrast, reduced motion, and larger system text.
- Ad-hoc RC packaging is suitable only for a small explicitly trusted tester group. It is not Developer ID signed or notarized, is expected to be rejected by Gatekeeper until the user grants a per-app exception, and does not qualify bookmark continuity across replacement, real denied/stale grants, external-volume replacement, clean-Mac quarantine launch, automatic update, rollback, or complete container removal.
- No exact byte delta or process attribution is inferred from FSEvents.
- Native qualification now includes controlled detach/remount and same-name replacement images on the development host. Oldest-supported-OS runtime behavior, genuine daemon `UserDropped`, `KernelDropped`, event-ID wrap, sleep/wake, and permission-revocation behavior remain unqualified; the permitted evidence boundary is recorded in the [continuity-loss qualification protocol](fsevents-continuity-qualification.md).
- Automatic post-start recovery is bounded and tested, but genuine daemon-generated drop/wrap conditions and recovery on the oldest supported macOS runtime remain unqualified.
- The raw-SQLite adapter now has schema-v11 immutable-ledger migration and digest checks, atomic backup/read-only recovery, v10/v11 canary fixtures, graph retention/History Off, retraction/effective reads, reproducible 500k/1M current-host repository benchmarks, production paired finalization, and a bounded application projector that drains newly registered work after commit and resumes persisted work at launch. GRDB parity, additional production-artifact recovery qualification, notarization, and oldest-OS runtime/performance evidence remain open.
- macOS 15.6 runtime qualification is not complete; compiling for the deployment target on a newer host is not runtime evidence.
- Full Disk Access, App Sandbox removal, Developer ID signing, notarization, distribution, and update behavior are unchanged and remain governed by their proposed decisions.
