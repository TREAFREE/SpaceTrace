## 已交付的核心产品链路

概览页现在会针对用户选择的 24 小时、7 天或 30 天窗口，展示一条有证据边界的链路：

```text
启动数据卷的可用空间减少
        |
        v
可比较授权根目录的 allocated-size 净增长
        |
        v
可归因部分（绝不会超过磁盘减少量）
        |
        v
仍然无法归因的余量
```

这是一种“对账”，不是物理磁盘块核算。它回答的是：“在已经获得授权、并且确实观测到的范围内，能够看见多少增长？”它不会把目录 allocated bytes 描述成 APFS 唯一物理块、立即可回收空间、Apple 的“系统数据”，也不会声称知道具体进程。

## 测量与生命周期

`FoundationStartupVolumeCapacityProvider` 读取 SpaceTrace Application
Support 目录所在卷的容量。应用完成正常组合后会立即记录一次，之后在进程保持运行时每小时记录一次。授权目录基线成功发布时，它的容量观测会和所有基线根目录放在同一个 SQLite 事务中提交。

如果系统 API 没有返回某个值，SpaceTrace 仍会保存一次“尝试过的观测”，但对应指标保持为空。未知绝不会被改写成 0。“重要用途可用空间”会作为独立字段保留，不会冒充“当前可用空间”。

生命周期任务由 `SpaceTraceAppDelegate` 持有，应用退出时会取消。它调用应用层拥有的 `StartupVolumeCapacityRecorder`；该用例只依赖 provider 与 repository 端口，因此 AppKit、Foundation 卷 API 和 SQLite 都仍然只是适配器。

## Schema v9

Schema v9 增加了：

- `startup_volume_capacity_sample`：使用 SQLite `AUTOINCREMENT` 单调序号，保存 UTC 观测时间、可选卷 UUID、容量字段，以及类型化的 `lifecycle` / `baseline` 来源；
- `authorized_baseline_root.volume_uuid`：归因不需要解析 opaque stream ID，也不会从挂载路径猜测卷身份；
- 容量历史最多保留 30 天；
- 从 v8 升级时，按稳定提交顺序迁移已有基线容量，并仅根据授权 bookmark 或最近挂载 generation 的证据保守回填根目录卷身份。

单调序号才是持久的观测顺序。系统时间用于分桶，但即使时间重复或回拨，也不能改变提交顺序。检测到时间回拨时，投影会降级为部分覆盖，并停止该窗口的端点归因，避免按错误的时间先后进行比较。released-schema golden fixtures 现在覆盖 v6、v7 和 v8。

## 归因规则

应用层在展示解释之前会执行以下规则：

1. 卷的两个端点必须都有可用空间，并且属于同一个已知的启动卷 UUID；卷被替换时会中断比较。
2. 只有持久化卷 UUID 与启动卷相同的根目录才是候选。已知位于外置卷的目录会被排除。
3. 卷身份未知的目录继续保持未知，并降低覆盖状态。
4. 候选目录中如果存在父子嵌套，只保留最上层根；父目录和子目录绝不会相加。
5. 每个保留根必须有两个 allocated-size 观测。先计算各根带正负号的端点变化，在互不重叠的根之间相加，最后才把负的净增长限制为 0。
6. 可归因部分为 `min(磁盘减少量, allocated-size 正净增长)`。
7. 无法归因余量为 `磁盘减少量 - 可归因部分`。

如果没有任何目录可以比较，那么“目录增长”“已解释”“无法归因”都会显示证据不足。SpaceTrace 不会直接把整段磁盘减少量说成“无法归因”，因为那样等于偷偷把“没有授权证据”当成“完整观测”。

## 覆盖状态与界面

缺少的小时/日时间桶会成为明确的 unavailable 点，并断开曲线。已知卷身份发生变化时也会断开容量曲线。界面同时使用文字、图标、点大小和无障碍标签表达覆盖状态，不只依赖颜色。

归因卡片会展示：

- “磁盘少了多少”：来自启动卷可用空间的两个端点；
- “授权目录能解释”：来自经过约束的 allocated-size 对比；
- “仍无法归因”：只有在目录证据可比较时才显示数值。

旁边的目录曲线和 Top 10 排名继续使用逻辑大小口径。Top 10 不会被求和，也不会被拿来充当归因总量。

界面会明确提醒：无法归因部分可能来自未授权或不可读位置、APFS 快照或克隆、系统与应用缓存、可清理空间行为，以及证据空白。它并不是“存在异常文件”的直接证据。

## 验证

- 应用层测试覆盖完整归因、只有卷历史时保持未知、父子根去重、外置卷排除和卷身份变化。
- SQLite 测试覆盖时间重复/回拨时的单调提交序号、基线与容量原子发布、根 UUID 往返、v8→v9 回填和容量 retention。
- MainActor / 展示层测试覆盖无目录时仍加载卷历史，以及遇到空白或卷替换时断开曲线。
- 带 SHA-256 的 released-schema fixtures 会把 v6、v7、v8 迁移到当前 schema。
- `make verify` 仍然是整个仓库的最终质量门禁。
